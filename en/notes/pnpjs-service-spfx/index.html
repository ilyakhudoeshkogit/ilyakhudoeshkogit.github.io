PnPjs in SPFx: one service for all lists

How the Executive Dashboard data service on PnPjs v4 is built: SPFx initialisation, select and filter, mapping the results.

The Executive Dashboard web part has three tabs: approvals, projects and documents. All of them read SharePoint lists, so I moved all data access into one SPService class. React components know nothing about REST, they get ready objects.

Initialisation

PnPjs v4 gets the web part context through the SPFx behaviour. It takes the token, the site URL and headers by itself.

import { spfi, SPFx, SPFI } from "@pnp/sp";
import "@pnp/sp/webs";
import "@pnp/sp/lists";
import "@pnp/sp/items";

export class SPService {
  private sp: SPFI;
  constructor(context: WebPartContext) {
    this.sp = spfi().using(SPFx(context));
  }
}

The @pnp/sp/webs, lists and items imports are added one by one, so only what is needed ends up in the bundle.

Only the fields you need

Every query lists its fields with select. A Person field needs expand, otherwise only the Id comes back.

const items = await this.sp.web.lists
  .getByTitle("Approvals").items
  .select("Id", "Title", "ApprovalType", "Status",
          "AssignedTo/Title", "AssignedTo/EMail")
  .expand("AssignedTo")
  .filter("Status eq 'Pending'")();

Diagram

The service catches errors itself and returns an empty array. This way one unavailable library does not break the whole page.
