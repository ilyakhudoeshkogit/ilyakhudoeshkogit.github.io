SharePoint list query builder: REST, PnPjs and Graph

Fill in the list, fields and conditions and get the same query three ways: a REST URL, a PnPjs chain and a Microsoft Graph request, plus hints about $expand, the 5000-item threshold and indexes.

I write the same list query as a URL for SPHttpClient, as a PnPjs chain, or for Microsoft Graph. The syntax differs a little each time and the mistakes are always the same: a missing $expand on a lookup field, an unescaped apostrophe, a date without datetime. So I built a builder that writes all three at once and points out where you will trip.

$filter

How to read the hints

A field with a slash, such as AssignedTo/Title, belongs to the linked item: the builder adds AssignedTo to $expand on its own. Graph does not expand these, it only returns AssignedToLookupId. If a list has more than 5000 items, index the filter and sort columns up front, not after the first production error.

The examples come from my projects: the PnPjs service in Executive Dashboard and bookings on two lists. The builder runs only in the browser and sends nothing anywhere.
