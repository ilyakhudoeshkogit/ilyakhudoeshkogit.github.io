Which Microsoft Graph permissions an SPFx web part should request

Tick what the web part does and get the least-privileged delegated scopes, a ready webApiPermissionRequests block for package-solution.json, an MSGraphClientV3 call and the approval commands.

When a web part needs Graph, the first impulse is to ask for User.Read.All and Sites.ReadWrite.All just to be safe. In SPFx that is a particularly bad idea: the grant goes not to your solution but to a principal shared by the whole tenant, and once approved any SPFx code uses it. So I built a picker: tick the tasks and see the narrowest scope for each, with the request and the code.

How approval works

The webApiPermissionRequests list turns into requests when the .sppkg is uploaded to the app catalog. An administrator sees them on the API access page of the SharePoint admin center or through PowerShell and approves them one by one. Until then a Graph call from the web part fails with an access error, so the code should show a clear message rather than an empty block.

Scopes are checked against the "Least privileged permissions" tables on the method pages of the Microsoft Graph reference and the SPFx docs on Entra ID-secured APIs, 2 Nov 2026. The picker runs only in the browser and sends nothing anywhere.
