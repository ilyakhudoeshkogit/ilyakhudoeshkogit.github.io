Desk booking on two SharePoint lists

The Desk Reservation data model: Desks and Reservations lists, a 1:N link, reads and writes via SPHttpClient with no separate backend.

The Desk Reservation web part needs no server of its own. Two lists are enough: Desks (desks: number, zone) and Reservations (who, which desk, which date). One desk can have many bookings on different dates.

Free desks for a date

The web part reads desks and bookings for the chosen date, then hides the booked ones. These are two GET requests via SPHttpClient.

const api = `${siteUrl}/_api/web/lists/getbytitle('Reservations')/items`;
const res = await spHttpClient.get(
  `${api}?$select=Id,DeskId,ReservedDate`,
  SPHttpClient.configurations.v1);
const booked = new Set((await res.json()).value
  .filter(r => r.ReservedDate.slice(0, 10) === day)
  .map(r => r.DeskId));
const free = desks.filter(d => !booked.has(d.Id));

Booking and cancelling

A new booking is a POST to Reservations, cancelling deletes the item. You can try the same logic in the live demo.
