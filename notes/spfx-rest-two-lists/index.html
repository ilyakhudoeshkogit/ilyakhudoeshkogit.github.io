Бронирование мест на двух списках SharePoint

Модель данных Desk Reservation: списки Desks и Reservations, связь 1:N, чтение и запись через SPHttpClient без отдельного сервера.

Для веб-части Desk Reservation не нужен свой сервер. Хватает двух списков: Desks (места: номер, зона) и Reservations (кто, какое место, на какую дату). Одно место может иметь много броней на разные даты.

Свободные места на дату

Веб-часть читает места и брони на выбранную дату, затем скрывает занятые. Это два GET-запроса через SPHttpClient.

const api = `${siteUrl}/_api/web/lists/getbytitle('Reservations')/items`;
const res = await spHttpClient.get(
  `${api}?$select=Id,DeskId,ReservedDate`,
  SPHttpClient.configurations.v1);
const booked = new Set((await res.json()).value
  .filter(r => r.ReservedDate.slice(0, 10) === day)
  .map(r => r.DeskId));
const free = desks.filter(d => !booked.has(d.Id));

Бронь и отмена

Новая бронь пишется POST-запросом в Reservations, отмена удаляет элемент. Попробовать ту же логику можно в живом демо.
