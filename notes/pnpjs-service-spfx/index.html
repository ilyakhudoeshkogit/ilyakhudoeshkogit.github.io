PnPjs в SPFx: один сервис на все списки

Как в Executive Dashboard устроен сервис данных на PnPjs v4: инициализация через SPFx, select и filter, разбор ответов.

В веб-части Executive Dashboard три вкладки: согласования, проекты и документы. Все они читают списки SharePoint, поэтому весь доступ к данным я вынес в один класс SPService. Компоненты React не знают про REST, они получают готовые объекты.

Инициализация

PnPjs v4 получает контекст веб-части через поведение SPFx. Токен, адрес сайта и заголовки он берёт сам.

import { spfi, SPFx, SPFI } from "@pnp/sp";
import "@pnp/sp/webs";
import "@pnp/sp/lists";
import "@pnp/sp/items";

export class SPService {
  private sp: SPFI;
  constructor(context: WebPartContext) {
    this.sp = spfi().using(SPFx(context));
  }
}

Импорты @pnp/sp/webs, lists, items подключаются по отдельности: так в бандл попадает только то, что нужно.

Только нужные поля

Каждый запрос явно перечисляет поля через select. Для поля «Пользователь» нужен expand, иначе придёт только Id.

const items = await this.sp.web.lists
  .getByTitle("Approvals").items
  .select("Id", "Title", "ApprovalType", "Status",
          "AssignedTo/Title", "AssignedTo/EMail")
  .expand("AssignedTo")
  .filter("Status eq 'Pending'")();

Схема

Ошибки сервис ловит сам и возвращает пустой массив. Так одна недоступная библиотека не ломает всю страницу.
